## 3. ChampScrape's concrete "plus points" (what to port)

Full architecture survey was done via deep-read agents on both repos. Key strengths found in ChampScrape that LakeStream lacked:

1. **Injectable-everything I/O design.** ChampScrape's `HTTPEngine(transport=...)` takes an injectable httpx transport; `RateGovernor`/`HumanPacer` take injectable `clock`/`rng`. This is *why* their whole test suite runs offline/deterministically via `httpx.MockTransport` and fake clocks instead of real sleeps or live network calls. LakeStream's fetchers have no such seams.
2. **No duplicated session/retry code.** ChampScrape centralizes retry+backoff+rate-limiting inside the one `HTTPEngine.fetch()`. LakeStream had the opposite: `_get_redis_client`/`_load_session`/`_save_session`/block-detection logic copy-pasted verbatim across 3 fetcher files (`lake_lightpanda_fetcher.py`, `lake_playwright_fetcher.py`, `lake_playwright_proxy_fetcher.py`).
3. **Registry pattern that's actually load-bearing.** ChampScrape's `@target(...)` decorator registry is enforced by a "no drift" test and is the single source of truth for dispatch. LakeStream had an equally well-built registry (`src/templates/registry.py` + `BaseTemplate` ABC, 5 platform implementations) that was **completely dead** — never called by the real scrape path.
4. **Provider/enrichment abstraction**: `EnrichmentProvider` ABC + Circuit Breaker + Chain-of-Responsibility (`enrichment/base.py`, `chain.py`). LakeStream had no circuit-breaker pattern anywhere for its external calls (Slack/webhook/email notifications in `signal_evaluator.py` have no such protection).
5. **Clean persistence abstraction** (`FactSink` ABC, graceful multi-sink fan-out) vs. LakeStream's **dead** `exporter/` files (`csv_exporter.py`, `pg_exporter.py` — zero callers) sitting next to `web.py`'s CSV export logic that was duplicated **twice**, verbatim, ~140 lines.
6. **Settings.describe() / redacted config endpoint** — good operational transparency pattern (shows what's configured without leaking secrets). *(Not yet ported — see §7 Remaining Work, optional/low-priority.)*
7. **`rigor.yaml`-style claim-honesty ledger** — a machine-checkable file of "true facts about this codebase" to stop AI-assisted docs/summaries drifting from reality. Novel process idea, orthogonal to code quality. *(Not ported — noted for awareness only, not in scope for this refactor.)*

ChampScrape weaknesses (confirmed NOT worth porting): no CI lint/type-check despite type hints, `logging` set up but never called, its own Redis-queue/worker-pool architecture is aspirational-only in its docs (unlike LakeStream's real arq-based queue, which is more mature — LakeStream wins here), `callback_url` field is unimplemented.

## 4. LakeStream's own bugs/violations found (independent of ChampScrape, discovered during the architecture audit)

- **Real correctness bug (confirmed, fixed)**: `src/api/middleware/auth.py:113-116` called `set_config('app.current_org_id', $1, true)` (transaction-local) on a connection acquired from a pool and released immediately after — did nothing useful, cost a wasted round-trip per JWT request, and the docstring misleadingly claimed it worked. RLS was already disabled at the DB level (`src/db/migrations/017_disable_rls.sql`) specifically because this pattern doesn't work with pooled connections. A second, differently-broken copy existed in `src/services/signal_evaluator.py:44-46` using f-string SQL interpolation (`SET LOCAL app.current_org_id = '{org_id}'`).
- **God-class**: `src/workers/content_worker.py` (512 lines) — mixed job orchestration, cancellation polling, heartbeating, content-type routing, 6 independent extraction strategies, link filtering, DTO assembly, and persistence all in one class. Zero test coverage before this refactor despite being the most complex/critical extraction logic in the app.
- **God-module**: `src/api/routes/web.py` (1585 lines) — auth pages (duplicating `src/services/auth.py`), raw SQL inlined in route handlers, CSV export logic **copy-pasted verbatim twice** (~140 lines: identical 30-field `fieldnames` list, identical `_join_list` helper, near-identical `writerow` blocks in `download_job_csv` and `download_all_csv`), and an **unsafe module-global monkey-patch** (`bulk_mod.STAGGER_DELAY_SECONDS = stagger_seconds`, restored in `finally`) that's not concurrency-safe if two bulk uploads with different stagger settings run at once.
- **LSP violation**: `src/workers/domain_mapper.py`'s `DomainMapperWorker` does NOT extend `BaseWorker` — different constructor, different `execute()` signature/return type, unthrottled heartbeat (vs. `BaseWorker`'s 30s-throttled one), no persistence method. `src/queue/jobs.py:97` has a comment acknowledging this ("DomainMapperWorker only accepts subset of parameters (not a BaseWorker)") and special-cases its construction.
- **Kitchen-sink service**: `src/services/signal_evaluator.py` (461 lines) mixes SQL signal-matching rules (4 near-duplicate `check_*_signal` functions) + 3 notification channel implementations (Slack/webhook/email) + audit logging + Redis pub/sub streaming, all as free functions with no internal class boundaries.
- **Dead code** (zero callers, confirmed by exhaustive grep): `src/scraping/parser/adaptor_parser.py`, `src/scraping/validator/data_validator.py`, `src/scraping/validator/email_validator.py` (note: `contact_parser.py` has its own separate, unrelated email regex — doesn't import this), `src/scraping/exporter/csv_exporter.py`, `src/scraping/exporter/pg_exporter.py`, `src/services/template_detector.py`.
- **Dependency manifest drift**: `pyproject.toml` and `requirements.txt` had non-overlapping package lists (`starlette`/`itsdangerous`/`python-multipart` only in `requirements.txt`; `mcp`/`pymupdf`/`pdfplumber`/`openai`/`typer` only in `pyproject.toml`) — real deploy risk if the wrong manifest is used for a given environment.
- **Templates registry disconnected**: `src/templates/` has a well-built `BaseTemplate` ABC + 5 platform strategies + registry, but `ContentWorker`'s real extraction path never called it. `template_id` was threaded end-to-end through the API/CLI/DB row but silently dropped before reaching `ContentWorker` construction in `src/queue/jobs.py`.
